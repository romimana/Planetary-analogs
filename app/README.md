# Planetary Analogs explorer

Open `index.html` in a browser. Choose a planetary target. Terrain only is the default. Mixed, Geochemistry-oriented and Terrain-oriented start with 25% for mapped geology where supported, and individual weights remain editable. Use the Earth sites filter to inspect the [survey windows](../TERRAIN_SURVEY.md) or the lab-sample locations. Choose a result to see feature distances, weighted group contributions, the original map labels and its map location. Use the zoom controls or scroll and drag the map. Focus centers the selected site. When served over HTTP or HTTPS, Focus also loads OpenStreetMap tiles. Opening the file directly uses the bundled Natural Earth coastline, with street-map and Google Earth links plus KML export for geographic detail.

## Rebuild

From the repository root, run `python build_app.py` with the project requirements installed. The builder verifies the public SQLite snapshots including [Earth expansion](../data/earth-expansion.sqlite) and [GEMAS](../GEMAS_PUBLIC.md), then bundles the HTML, CSS, JavaScript and data. Run `node app/recommend_samples.js` and rebuild if data or ranking changes. To serve locally, run `python serve_app.py` and open `http://127.0.0.1:8000`.

## Ranking and sources

- [Data and coverage](../DATA_CODEBOOK.md) defines the features and their spatial support. The ranking calculates distances on demand for the current target. Chemistry uses centered log ratios. Chemistry and terrain use Earth interquartile ranges for scaling and a bounded RMS within each group. The feature table displays the absolute distance in standardized units for those two groups. The group cards display the bounded distance, normalized weight, and weighted contribution.
- [Geology](../GEOLOGY_MATCHING.md) uses the documented rubric. Where unavailable for the selected target, the app normalizes the active weights. If geology is active, Earth candidates must have a mapped class. RADARSAT-1 scene links are shown for candidates with those historical observations.
- Solar uses the absolute difference in the horizontal projection for the selected UTC scenarios. See the [SPICE audit](../data/solar-audit.json). Surface illumination and mapped geology support initial screening.
- Earth region and site pool filter the global score output. Numeric scales fit independently on valid Earth values for each active group across all regions. With chemistry enabled, each ranked row has the selected measured components. The app reports eligible counts by region. The global top ten may all come from a single country. The data include distinct surveyed materials and analytical methods, so use geographic and source coverage in interpreting the rankings.
- Mars image by [NASA/JPL-Caltech](https://science.nasa.gov/resource/mars-planet-globe/). Land polygons from [Natural Earth 1:110m](https://www.naturalearthdata.com/downloads/110m-physical-vectors/110m-land/), release 5.1.2.
- Interactive mapping uses [Leaflet 1.9.4](https://leafletjs.com/reference-1.9.4.html) under its [BSD-2-Clause license](assets/leaflet-LICENSE). Online detail uses © [OpenStreetMap contributors](https://www.openstreetmap.org/copyright).

The Irish GSI and USGS additions, selection criteria and provenance are documented in [Earth expansion](../EARTH_EXPANSION.md).

## Mission area, sunlight and explanations

- The measurement picker includes every measurement for the selected body. The Recommended group highlights demonstration targets evaluated with all regions, four profiles, default chemistry components, and sunlight off. Each recommended target has at least two regions in the top ten of every tested profile and at least two distinct first-place regions across profiles. The first sort key is the worst geographic concentration across profiles. Each profile gets an effective region count of 100 divided by the sum of squared regional counts in the top ten. A 9-to-1 split scores 1.22, while a 5-to-5 split scores 2. No mission area is guaranteed a recommendation. Records marked as held for chemistry and records with FAILED in the source label are excluded from demo recommendations and stay selectable in the full picker. Recommendations select demonstration cases and give no bonus to individual analogs. The [reproducible report](../data/recommended-samples.json) identifies each top result. Recorded material, sol where available, location precision and source links are shown for every target.
- There are 149 Mars and 12 Moon measurements. Twelve Mars records held by the chemistry quality screen are selectable for terrain and supported mapped geology. They have no archived solar scenarios. The active weights are renormalized when a comparison group is unavailable.
- **Best match per country or territory** takes the first ranked candidate in each mapped region and shows up to ten regions. The tool computes the same candidate scores either way.
- **Include a sunlight scenario** selects up to four distinct positive target solar projections spanning the archived daylight range. For each Earth candidate, it checks the selected target projections against all positive Earth projections in the 24 stored scenarios and minimizes the absolute difference. Ties are resolved by the target projection order and then Earth time order. The list shows the Earth reference date and time. The details show both dates and times in UTC. These are modeled historical scenarios. The geometry supplies no forecasts, terrain shadows, atmospheric attenuation or local clock conversion.
- The built-in factual explanation always uses the selected record and the numeric breakdown. Enable hosted Gemini by setting `GEMINI_API_KEY` as a server secret and running `python serve_app.py`. Open `http://127.0.0.1:8000`. The **Explain with Gemini** button sends the selected public comparison to the same-origin endpoint. The server sends only the supplied comparison context to Gemini and displays its prose beside the factual scores. For a hosted demo, run the same command in a Python web service, set `ANALOGS_HOST=0.0.0.0` and configure the service's `PORT`. The default model is `gemini-3.1-flash-lite`, configurable through `GEMINI_MODEL`. See [Gemini pricing and quotas](https://ai.google.dev/gemini-api/docs/pricing). The default server budget is 50 attempts per UTC day per process, adjustable with `ANALOGS_DAILY_REQUESTS`. Without a key, the factual explanation still works. Live Gemini requires the project's API key and model access.
